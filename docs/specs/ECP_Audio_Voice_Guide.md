# English Conversation Partner — Audio & Voice Implementation Guide

**Audience:** The AI coding agent (Antigravity) and the human reviewer.
**Read first:** `English_Conversation_Partner_Project_Brief.md` (§8 Audio, §9 AI Speaking Partner, §17 Engineering), `ECP_System_Framework.md` (§6 Audio System, §7 Data Model), `ECP_Multi_Language_Strategy.md` (§4.3 audio_assets, §10 Audio and Language).
**Constraint:** Use only free tools, free tiers, and open-source models. Do not add any paid service without explicit approval (brief §20, rule 18).
**Status:** Implementation guide. Requires approval of decisions in §16 before Phase 1 audio work starts.

---

## 0. Rules for the Agent (read before doing anything)

1. **Free only.** Every tool in this guide is free and open-source, or has a free tier. If a step seems to need a paid service, stop and ask.
2. **Verify before you trust.** Free voice models have different licences. Check the licence of each voice file and each external audio file before using it. Record it in `docs/AUDIO_LICENSES.md`.
3. **Never fake audio.** If an audio file does not exist, the UI shows "Audio not available yet". Never play a placeholder tone or a different sentence.
4. **Generate offline, serve static.** Audio is generated by an admin script, saved to storage, and served as a file. Do not call a TTS engine from the learner's request path.
5. **Language must match voice.** English text uses English voices only. Bangla text does not get audio in MVP (see §2).
6. **No autoplay.** Audio starts only after a user click or tap.
7. **Keep the English text visible.** Audio never replaces the written sentence. A transcript is always shown.
8. **Ask before big choices.** If the voice quality is poor, ask the reviewer to choose from the candidates in §3.3 rather than picking one silently.

## 3. Voice Strategy

### 3.1 Voice roles

Each dialogue has speakers. Each speaker role maps to a voice from a fixed set, so the same role sounds the same across scenarios.

| Voice role | Accent | Example voice (verify names in the catalogue) |
|---|---|---|
| `female_1` | en-US | US female voice |
| `male_1` | en-US | US male voice |
| `female_2` | en-GB | UK female voice |
| `male_2` | en-GB | UK male voice |
| `narrator` | en-US or en-GB | Used for scenario intro if needed |

Minimum 2 voices per accent so dialogues have clear speaker differences. Recommend 4 per accent for variety.

### 3.2 Voice configuration file

Store voice mapping in a versioned file, not in code.

`content/audio/voices.json`:

```json
{
  "config_version": 1,
  "provider": "piper",
  "voices": [
    {
      "voice_key": "en-US:female_1",
      "language_code": "en-US",
      "provider_voice_id": "en_US-lessac-medium",
      "model_path": "models/piper/en_US-lessac-medium.onnx",
      "licence": "CHECK_MODEL_CARD",
      "speed_default": 1.0,
      "status": "approved"
    }
  ]
}
```

Rules:
- `provider_voice_id` must match an installed model file.
- `status` must be `approved` before the voice is used for learner audio.
- Changing a voice changes the `source_hash` (see §5.2), so audio is regenerated rather than mixed.

### 3.3 Voice selection process (human step)

1. Agent generates the same 10 test sentences with each candidate voice.
2. Reviewer listens and scores each voice (1–5) for clarity, naturalness, pacing, and pronunciation of names and numbers.
3. Reviewer approves the voices, and the agent updates `voices.json` with `status: approved`.

Test sentences file: `content/audio/test_sentences.txt`. Include:
- A question ("Could you tell me where the station is?")
- A number and price ("That's twenty-five dollars.")
- A time ("I'll be there at 3:30.")
- A name ("Hi, I'm Priya.")
- An abbreviation ("Dr. Rahman will see you now.")
- A contraction ("I'm not sure, but I'll check.")
- A long sentence with a comma pause.
- An emphasis sentence ("No, I didn't say that.")
- An informal phrase ("Yeah, sounds good.")
- A formal phrase ("I would appreciate it if you could confirm by Friday.")

## 4. Generation Pipeline (offline, admin-triggered)

### 4.1 Overview

```
DialogueLine (English text, speaker)
   │
   ▼
Normalise text  ──►  Compute source_hash
   │                       │
   │               already exists? ──yes──► reuse AudioAsset
   │                       │ no
   ▼                       ▼
Piper TTS (WAV)  ──►  FFmpeg loudness normalise  ──►  encode MP3
   │
   ▼
Save file to storage  ──►  Insert/Update AudioAsset (status = ready)
   │
   ▼
Assemble full conversation (sentences + pauses)  ──►  Timing manifest JSON
```

### 4.2 Text normalisation (before TTS)

Apply in this order:
1. Trim spaces; collapse repeated spaces.
2. Replace curly quotes with straight quotes for the TTS input (keep the original text in the DB).
3. Expand common abbreviations for speech: `Dr.` → `Doctor`, `St.` → `Street`, `vs.` → `versus`. Store the spoken form in `tts_text`, keep `english_text` unchanged.
4. Keep numbers as written. Check the audio: some engines read "3:30" oddly. Add `tts_text` override when needed (for example "three thirty").
5. Do not remove punctuation; it controls pauses and intonation.

Add a column to `dialogue_lines` or to `audio_assets`: `tts_text` (nullable) — when present, it overrides the spoken form.

### 4.3 Hash and idempotency

```
source_hash = sha256(
  tts_text + "|" + voice_key + "|" + provider_voice_id +
  "|" + speed + "|" + PIPELINE_VERSION
)
```

- If an `audio_assets` row with the same `source_hash` and `status = ready` exists, skip generation.
- `PIPELINE_VERSION` is a constant in code. Change it when audio processing changes (for example new loudness target), which forces regeneration.

### 4.4 Generating a sentence with Piper (conceptual)

Use Piper from the command line through a Python wrapper. Piper's exact flags can change between releases, so the agent must check `piper --help` for the installed version and adjust.

```bash
# Conceptual example; verify flags against installed Piper version
echo "Could you tell me where the station is?" \
  | piper --model models/piper/en_US-lessac-medium.onnx \
          --output_file tmp/line_000123.wav
```

For speaking speed, use Piper's length-scale option if available in the installed version (lower value = faster). Keep the default speed in MVP and use the browser `playbackRate` for learner speed control.

### 4.5 Post-processing with FFmpeg

```bash
# 1. Normalise loudness to a consistent level (speech target)
ffmpeg -y -i tmp/line_000123.wav \
  -af "loudnorm=I=-16:TP=-1.5:LRA=11" \
  -ac 1 -ar 44100 \
  tmp/line_000123_norm.wav

# 2. Encode to MP3 for delivery
ffmpeg -y -i tmp/line_000123_norm.wav \
  -codec:a libmp3lame -b:a 96k \
  storage/audio/en-US/female_1/3f9a...c1.mp3
```

Notes:
- MP3 is supported by all target browsers. Do not use OGG-only.
- 96 kbps mono is enough for speech. Keep file sizes small (brief §17.4).
- Filename uses the `source_hash` so the same content is never stored twice.

### 4.6 Quality checks (automatic)

Run after each generated file. Fail the asset (status `failed`) if any check fails.

| Check | Rule | Reason |
|---|---|---|
| Duration | Between 0.3 s and 30 s for a line | Catches empty or runaway audio |
| Duration ratio | Between 0.5x and 3x of expected (characters / 14 per second) | Catches cut-off or stuttering output |
| Silence | Leading and trailing silence each under 0.5 s after trim | Removes dead air |
| Clipping | Peak below -1 dBFS | Avoids distortion |
| Loudness | Within ±2 LUFS of target | Consistent volume between lines |
| Format | MP3, mono, 44.1 kHz | Consistent playback |

Implement these checks in `scripts/audio/check_asset.py` using `ffprobe` and `ffmpeg -af volumedetect` or `ebur128`.

## 5. Data and Storage

### 5.1 `audio_assets` table (aligned with Multi-Language Strategy §4.3)

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | PK |
| `source_type` | text | `dialogue_line`, `vocabulary`, `conversation_full` |
| `source_id` | uuid | Target row |
| `language_code` | text | `en` (base) — accent in separate column |
| `accent` | text | `en-US`, `en-GB`, null for non-English |
| `voice_key` | text | e.g. `en-US:female_1` |
| `provider` | text | `piper` |
| `provider_voice_id` | text | Model name |
| `source_hash` | text | Unique |
| `storage_key` | text | Path in bucket or local folder |
| `duration_ms` | int | From ffprobe |
| `byte_size` | int | For monitoring storage |
| `status` | text | `pending`, `ready`, `failed`, `stale` |
| `pipeline_version` | int | Matches constant in code |
| `licence` | text | Copied from voice config |
| `created_at` | timestamptz | |

Indexes: unique `source_hash`; index on `(source_type, source_id, accent)`.

### 5.2 Full conversation timing manifest

Stored as JSON, one per conversation version and accent. Used for the progress bar, line highlight, and "jump to line".

`storage/audio/manifests/<conversation_version_id>/en-US.json`

```json
{
  "conversation_version_id": "uuid",
  "accent": "en-US",
  "full_audio_key": "storage/audio/full/<hash>.mp3",
  "duration_ms": 84250,
  "pause_between_lines_ms": 600,
  "lines": [
    { "line_id": "uuid", "sequence": 1, "speaker": "Ticket agent", "start_ms": 0,    "end_ms": 2810 },
    { "line_id": "uuid", "sequence": 2, "speaker": "Passenger",    "start_ms": 3410, "end_ms": 6020 }
  ]
}
```

Rules:
- Line times are derived from the actual durations, not estimated.
- If any line audio is missing, the full conversation audio is not built. The UI shows the full-audio control as "Full audio not available yet" and sentence audio still works.

### 5.3 Full conversation assembly

1. Load sentence WAVs in `sequence` order (use the normalised WAVs, before MP3).
2. Insert a silence of `pause_between_lines_ms` (600 ms default) between lines; use a longer pause (900 ms) when the speaker changes.
3. Concatenate with the FFmpeg concat demuxer.
4. Normalise loudness again on the full file.
5. Encode to MP3, save, and write the manifest.

Silence file (create once):

```bash
ffmpeg -f lavfi -i anullsrc=r=44100:cl=mono -t 0.6 storage/audio/silence_600ms.wav
```

## 7. Frontend Implementation

### 7.1 Components

| Component | Responsibility |
|---|---|
| `AudioButton` | One sentence. States: `idle`, `loading`, `playing`, `paused`, `error`, `unavailable`. |
| `FullAudioPlayer` | Whole conversation. Play, pause, replay, speed, progress, current line. |
| `SpeedControl` | Chooses 0.75x, 1x, 1.25x, 1.5x, 2x. Persists in user preferences. |
| `AudioProvider` (context) | Holds one shared `<audio>` element so only one clip plays at a time. |
| `WordAudioButton` | Plays a vocabulary word. Used in the vocabulary popover. |

### 7.2 Behaviour

- **One audio at a time.** Starting a new clip stops the current one.
- **Shared element.** Use one `HTMLAudioElement` in `AudioProvider` and change its `src`. This avoids many players competing.
- **Speed.** Set `audio.playbackRate` on every new clip. Browsers keep pitch correct.
- **Replay.** Set `currentTime = 0` and play.
- **Full audio line highlight.** Listen to `timeupdate`, find the current line from the manifest, highlight it in the dialogue, and make the highlight visible without colour alone (use a left bar and bold text).
- **Jump to line.** Clicking a line in the dialogue sets `currentTime` to that line's `start_ms / 1000`.
- **Errors.** If loading fails, show "Audio could not load" with a Retry button. Retry at most 2 times automatically with a short delay, then wait for the user.
- **Unavailable.** If `audio_assets` has no `ready` row, the control is shown in a disabled state with the text "Audio not available yet". It is not hidden, so the learner knows it exists.

### 7.3 Accessibility

| Requirement | Implementation |
|---|---|
| Keyboard | Every control is a `<button>` (Tab reachable). Space and Enter toggle play. Left/Right arrows seek 5 seconds in the full player. |
| Labels | `aria-label="Play line 3, Passenger"`, `aria-label="Pause full conversation"`, `aria-label="Playback speed 1.25x"`. |
| State | Use `aria-pressed` for toggle states and `aria-live="polite"` for status text (for example "Playing line 3"). |
| Transcript | The English text is always rendered, so audio is never the only source of information. |
| Focus | Visible focus ring from the design tokens. |
| Motion | No animated waveform in MVP. If added, respect `prefers-reduced-motion`. |
| Captions | The English sentence is the caption. Full-audio mode shows the current line. |
| Language | Each audio region sits inside an element with `lang="en"` (or the correct accent variant). |

### 7.4 Mobile

- Sticky bottom bar for full audio on small screens, with `padding-bottom: env(safe-area-inset-bottom)` (see the published-page rules if the app is ever published as an artifact).
- Touch targets at least 44 × 44 px.
- Background playback is not guaranteed on iOS Safari; show a note in settings if the learner asks.
- Playback must start from a user tap, which browsers require.

### 7.5 Sample code sketch (for the agent to adapt)

```tsx
// components/learning/AudioButton.tsx — conceptual
"use client";
import { useAudio } from "@/features/audio/AudioProvider";

export function AudioButton({ lineId, sequence, speaker, src }: Props) {
  const { play, state, currentId } = useAudio();
  const isThis = currentId === lineId;
  const label = `${isThis && state === "playing" ? "Pause" : "Play"} line ${sequence}, ${speaker}`;

  if (!src) {
    return (
      <button type="button" disabled aria-label={`Audio not available for line ${sequence}`}>
        Audio not available yet
      </button>
    );
  }

  return (
    <button type="button" aria-label={label} onClick={() => play(lineId, src)}>
      {isThis && state === "playing" ? "Pause" : "Play"}
    </button>
  );
}
```

## 9. Learner Recording (Phase 2)

Purpose: learners record their own sentence, compare with the model audio.

| Item | Rule |
|---|---|
| API | Browser `MediaRecorder` (free, built in). Produces WebM or MP4 depending on browser. |
| Permission | Ask microphone access only when the learner clicks "Record". Explain why in one sentence. |
| Storage | **Default: keep the recording on the device only** (IndexedDB), not on the server. Uploading is opt-in. |
| Deletion | Learner can delete any recording at any time. |
| Playback | Compare side by side with model audio. |
| Privacy | Do not collect voice data for training. Say so in the privacy page. |
| Fallback | If the browser does not support `MediaRecorder`, hide the record button and show a short message. |

Note: IndexedDB is fine for this, because the recording is the learner's own user data and not a shared artifact. The agent should still confirm this rule with the reviewer before implementation.

## 10. Speech Recognition and Pronunciation (Phase 3)

### 10.1 Options (free first)

1. **Whisper via whisper.cpp or faster-whisper (local, free).** Good for transcribing a learner's spoken answer to check roleplay responses. Run it on a server or in a local helper. Not practical in the browser for weak devices.
2. **Web Speech API (browser, free).** Simplest. Accuracy varies. In some browsers, audio goes to the vendor. Show a privacy note before enabling.
3. **Azure Speech pronunciation assessment (free tier, limited).** Gives word-level and phoneme-level scores. Free quota is limited. Requires approval because it becomes paid above the quota.

### 10.2 Rules for pronunciation feedback (brief §9.3)

- Never show a single "pronunciation score" as objective fact.
- Say what was heard, which words were unclear, and suggest one thing to practise.
- Explain the limits: "This is an automatic check and may not match a teacher's judgement."
- Use relative feedback ("the 'th' sound in 'three' was unclear") rather than percentages.

## 11. Error and Fallback Behaviour

| Situation | Learner sees | System does |
|---|---|---|
| No audio file for a line | Disabled button "Audio not available yet" | Logs missing asset for admin |
| File exists but fails to load | "Audio could not load" + Retry | Retries 2 times, then waits |
| Browser blocks playback | Button stays in `idle`; message "Tap play to listen" | No retry loop |
| Full audio manifest missing | "Full audio not available yet" | Sentence audio still works |
| Manifest references a missing file | Full audio disabled | Admin dashboard flags the scenario |
| Network offline | "You are offline. Audio will play when you are back online." | No infinite spinner |
| Slow network | Loading state with a timeout after 10 s | Shows Retry |
| Voice changed after publish | Old audio stays until regenerated | Admin sees `stale` status |

## 12. Admin and Content Workflow

Matches framework §5 (content pipeline).

1. Editor finalises English dialogue (status `ready_to_publish`).
2. Admin clicks **Generate audio** for the version. The job runs in the background (offline script, not the learner request path).
3. Each line is checked (§4.6). Failed lines are listed.
4. Reviewer listens to the full audio and the sentence list, marks each line `audio_approved`.
5. Scenario can be published with missing audio (framework §5.3). Missing lines show "Audio not available yet".

Admin UI requirements:
- Button "Generate audio" per version and accent.
- Table of lines with status: `ready`, `failed`, `missing`, `stale`.
- Button "Regenerate line" for one line.
- Storage usage shown (total MB, count of files) — useful for free-tier limits.

## 15. Implementation Steps for the Agent

Follow in order. Stop at each approval point.

### Step 1 — Environment (no product code yet)
1. Install Python 3.11+ and FFmpeg (free).
2. Install Piper (free) and download the approved voice models from the official Piper voices repository on Hugging Face. Record each model's licence.
3. Create `docs/AUDIO_LICENSES.md` with a table: voice, source URL, licence, date checked.

## 17. Things the Agent Must NOT Do

1. Do not use gTTS, edge-tts, or any unofficial endpoint in production audio without a licence review and reviewer approval.
2. Do not use paid TTS APIs (ElevenLabs, Azure TTS, Google Cloud TTS) unless approved. They are not free beyond limited trials.
3. Do not call any TTS engine from a learner's request.
4. Do not put API keys or secrets in audio scripts (none are needed here).
5. Do not autoplay audio.
6. Do not generate Bangla audio in MVP.
7. Do not commit large audio files to git. Keep them in storage; commit only the scripts, configs, and manifests.
8. Do not use Forvo, proprietary dictionary audio, or any file without a clear licence.
9. Do not hide the English text when audio plays.
10. Do not show a fake pronunciation score.

## 18. Free-Tier and Cost Checks

| Item | Check before production |
|---|---|
| Piper and voice model licences | Confirmed and recorded in `docs/AUDIO_LICENSES.md` |
| Cloudflare R2 free limits | Current storage, class A and B operations, and egress terms checked |
| Hosting bandwidth | Estimated audio bytes per learner session, and total per month |
| Compute for generation | Time per line measured on the dev machine; estimated total time for full content |
| Upgrade trigger | Written in `docs/DECISIONS.md`: when free limits are exceeded, the admin must approve before moving to a paid plan |

Estimate before generating a large library:
- Average line: about 5 seconds, about 60 KB as MP3 at 96 kbps.
- A 15-line conversation in one accent: about 75 seconds, about 1 MB including full audio.
- Storage for 100 conversations, two accents, sentence plus full audio: roughly 200–300 MB. Check against the free tier.

Audio work is complete when:

- [ ] Approved voices are recorded in `voices.json` and `AUDIO_LICENSES.md`.

- [ ] Full conversation audio plays, with working seek and line highlight.

- [ ] Missing audio shows the unavailable state, and the page does not break.
- [ ] No audio plays without a user action.
- [ ] Keyboard and screen reader labels pass a manual check.
- [ ] Quality checks run on every generated asset.
- [ ] Generation scripts are idempotent and documented.
- [ ] No paid service is used, and no unofficial endpoint is used in production.
