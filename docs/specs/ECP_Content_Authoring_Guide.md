# English Conversation Partner — Content Authoring Guide

**Fills gap:** G-04 in `ECP_Review_Report.md`.
**Brief sources:** §2.2 (CEFR), §4 (conversation structure), §5 (learning flow), §6 (grammar), §7 (translation), §20 (risks 1–3, 6, 8).
**Used by:** Editors, translators, reviewers, and the agent when it imports or drafts content.
**Status:** Guide for approval. Owner must name the reviewers listed in §10.

---

## 1. Principles

1. **Human-reviewed before publish.** AI can draft. A named reviewer approves. Nothing is published on AI output alone (brief §20 risk 1).
2. **Real speech, not textbook sentences.** The dialogue must sound like people talking.
3. **One scenario, many versions.** Versions add depth. They do not repeat lines to look longer (brief §4.2).
4. **Context decides meaning.** Every translation and grammar note refers to the actual sentence.
5. **Do not give professional advice.** Legal, medical, and financial content teaches language only (brief §20 risk 6).
6. **Consistency beats variety.** Use the same term for the same thing across the library (glossary, §8).

## 2. Scenario Writing

### 2.1 Required scenario fields

| Field | Rule |
|---|---|
| Title | Sentence case. Describes the situation. "Asking for a refund", not "Refund conversation". 3–8 words. |
| Description | One or two sentences a learner understands without context. |
| Context | 2–4 sentences: where, who, why. |
| Learning objective | One sentence: "Ask for a refund politely and state the problem clearly." |
| Level | One of A1–C2 (see §4). |
| Estimated duration | Minutes. Short version ≈ 2, medium ≈ 4, long ≈ 8 (estimate, not measured). |
| Categories | At least one (DB §5.6). |
| Professions | Optional. Only for professional content. |
| Adaptability | `translate` or `adapt` (for currency and local examples, Multi-Language §14). |

### 2.2 Scenario selection for Phase 1

Target from the Phase Plan: 12 daily-life scenarios and one professional path of 5 conversations. Choose scenarios that teach high-use situations for the target learner:

- Shopping and money: asking for a price, returning an item, paying.
- Travel: buying a ticket, asking directions, checking in at a hotel.
- Health: booking an appointment, describing a symptom, understanding a prescription.
- Social: introducing yourself, cancelling plans politely, apologising, disagreeing politely.
- Workplace: asking a manager for two more days, reporting a delay, submitting a file.

Do not write a scenario only because it is interesting. Each scenario must be something a learner is likely to need.

## 3. Dialogue Writing Rules

### 3.1 Versions and lengths

| Version | Exchanges (lines) | Purpose |
|---|---|---|
| Short | 4–6 | Quick beginner practice |
| Medium | 8–12 | Fuller interaction |
| Long | 15–25 | Detailed interaction, includes a complication or change of direction |

Each longer version must add something: a new piece of information, a complication, a follow-up question, a choice. If the Long version only repeats the Short one with extra "okay" lines, it is rejected.

### 3.2 Line rules

- One sentence or one short phrase per line. Maximum about 25 words; prefer under 15 for Short versions.
- Use contractions in casual and neutral styles (`I'm`, `don't`, `it's`). Avoid them in formal style only where the situation demands it.
- Use real fillers in casual dialogue (`Yeah`, `Well`, `Hmm`), not in formal dialogue.
- Avoid rare idioms in Short and Medium versions. In Long versions, one idiom per scenario may appear, with a learning note.
- Numbers, times, and prices are written in a form a learner would hear: "twenty-five dollars", "3:30" (audio override in `tts_text`, Audio Guide §4.2).
- No slang that dates quickly ("lit", "bussin"). If slang is needed for a realistic casual scene, add a learning note.

### 3.3 Speaker rules

- Each speaker has a role, not only a name: "Ticket agent", "Passenger".
- Speaker count: 2 for Short and Medium, up to 3 for Long.
- Speaker names reflect a range of backgrounds without stereotype. Avoid assumptions about gender, religion, or nationality tied to a job or behaviour.
- Speakers have a consistent voice across scenarios (Audio Guide §3.1).

### 3.4 Style rules

| Style | Use for | Example feature |
|---|---|---|
| Casual | Friends, family, close colleagues | "Hey, you coming?" |
| Neutral | Everyday services, most workplace talk | "Could you tell me where the station is?" |
| Formal | Professional, official, first meetings with authority figures | "I would appreciate it if you could confirm by Friday." |

A conversation with a close friend must not sound like a legal letter (brief §4.3).

### 3.5 Learning note rules

- Optional per line. Maximum 2 sentences.
- Explains a choice the learner might miss: why "Could" is more polite than "Can", why the speaker says "I'm afraid".
- Does not explain basic words.
- Written in English. Bangla explanation is added through translation or gloss, not in the English note.

### 3.6 Forbidden content

- Stereotypes about any nationality, religion, gender, or profession.
- Content that encourages harm, self-harm, discrimination, or illegal acts as a model.
- Invented facts presented as real: names of real businesses, real phone numbers, real addresses.
- Real people's names, quotes, or identities.
- Medical, legal, or financial instructions presented as advice.

## 4. Level Assessment (CEFR-inspired)

Brief §2.2: CEFR labels must not be assigned casually. Assign level by checking the **version**, not the scenario.

### 4.1 Checklist

| Signal | A1 | A2 | B1 | B2 | C1–C2 |
|---|---|---|---|---|---|
| Sentence length | 3–6 words | 6–10 | 10–15 | 15–20 | 20+ |
| Tenses | Present simple | + past simple, future with "going to" | + present perfect, conditionals type 1 | + most tenses, conditional types 2–3 | Full range, nuance |
| Vocabulary | Core high-frequency | Everyday | Wider everyday, some topic words | Abstract, professional | Idiomatic, specialised |
| Implied meaning | Very little | Little | Some | Frequent | Frequent, subtle |
| Speed (speaker pace in audio) | Slow, clear | Normal, clear | Normal | Natural | Natural, fast |

Rules:
- A version takes the level of its hardest signal. One complex sentence can raise the level.
- The scenario level is the level of its Normal version.
- Reviewer re-checks levels for 20% of scenarios at random before publish.

### 4.2 Difficulty labels

Easy / Normal / Hard are within a level, not a different level. Easy uses shorter lines and fewer new words. Hard uses longer lines and more implied meaning.

## 5. Translation Guide (Bangla)

Brief §7.3: translate naturally, preserve intent and politeness, explain idioms by meaning.

### 5.1 Principles

1. **Meaning and tone first.** A polite English request is a polite Bangla request. Use the Bangla equivalent a native speaker would say, not a word-for-word copy.
2. **Match the register.** Casual English → casual Bangla (তুমি / তুই as appropriate for the relationship shown). Formal English → formal Bangla (আপনি).
3. **Keep alignment.** One Bangla translation per English line. Do not merge or split lines.
4. **Do not add information.** Do not add a fact that the English does not state.
5. **Idioms explained by meaning.** Translate the meaning, and add a learning note if the literal meaning would mislead.
6. **Names and places stay in English** unless a standard Bangla form exists (for example, "Dhaka" stays "ঢাকা" in Bangla text). Keep the name consistent with the glossary.

### 5.2 Pronoun and address rules

| English | Casual Bangla | Formal Bangla |
|---|---|---|
| you (friend, peer) | তুমি | আপনি |
| you (close friend, younger) | তুই (only if the English context is very informal and the reviewer agrees) | — |
| you (staff, stranger, official) | আপনি | আপনি |

Default for Bangla translations: **আপনি** unless the scene is clearly between close friends or family. Reviewer decides edge cases and records them in the glossary notes.

### 5.3 Quality checks for translators

- [ ] Same number of lines as English.
- [ ] Meaning matches, including politeness and intent.
- [ ] No English words left in Bangla text, except names, brand names, and terms in the glossary.
- [ ] Bangla text uses correct Unicode (no mixed-up characters). Run NFC normalisation (Multi-Language §8.4).
- [ ] Numbers in Bangla text use the chosen numeral style consistently (Bangla or Western digits, per glossary).
- [ ] No machine-output artifacts: "Here is the translation:", extra quotes, bullet points.

### 5.4 Glossary

Maintained in `messages/glossary.md` for UI copy and in the `glossary_terms` table (Multi-Language §9.3) for content. One entry per term:

| source_term | target_term (bn) | domain | note |
|---|---|---|---|
| deadline | সময়সীমা | general | |
| refund | রিফান্ড / টাকা ফেরত | shopping | Use "টাকা ফেরত" in dialogue, "রিফান্ড" in UI if the owner agrees |

## 6. Grammar and Vocabulary Notes

Brief §6.3: explain in simple language, use the actual sentence, do not invent rules.

### 6.1 Sentence-level grammar note (required fields)

| Field | Example |
|---|---|
| Sentence | "I'll check and let you know." |
| Meaning in context | The speaker promises a future update. |
| Structure | I'll (I will) + check (verb) + and + let you know (infinitive phrase) |
| Tense or form | "will" for a decision made now. |
| Common learner mistake | "I check and let you know" (missing future). |
| Alternative | "I'll look into it and get back to you." |

Rules:
- Use the sentence as context in every field.
- Do not show a field that does not apply (for example, no "tense" for a fragment).
- Keep to one main point per note.

### 6.2 Word-level note

Include only what applies (brief §6.1, §20 "do not force properties"):

- Meaning in this sentence.
- Part of speech **in this sentence**.
- Forms: only if the word has useful forms (for example, "refund" → "refunds", "refunded").
- Synonym or collocation: only if the learner can use it.
- Example sentence: one, from the scenario or new.

Never list an antonym for a word that has none in practice.

### 6.3 Automatic checks (before reviewer)

Run through the NLP service (framework §12):
- Stated part of speech matches the spaCy tag in the sentence.
- Stated subject and verb exist in the sentence.
- Tense claimed matches the verb form.

Failures go to the reviewer with the reason.

## 7. Import Format (JSON)

Editors can import drafts. The importer validates each file against the Zod schema and rejects the whole file on any error (no partial import).

Example:

```json
{
  "schema_version": 1,
  "scenario": {
    "slug": "return-a-damaged-item",
    "title": "Returning a damaged item",
    "description": "You bought something that arrived broken and you want to return it.",
    "context": "You are at a shop counter. The item is damaged and you have the receipt.",
    "learning_objective": "Explain a problem and ask for a refund or exchange politely.",
    "level": "A2",
    "estimated_duration_minutes": 4,
    "categories": ["shopping-money"],
    "professions": []
  },
  "versions": [
    {
      "length_type": "short",
      "communication_style": "neutral",
      "level": "A2",
      "version_name": "Short: at the counter",
      "speakers": [
        { "key": "shop", "name": "Shop assistant", "role": "Staff" },
        { "key": "cust", "name": "Customer", "role": "Customer" }
      ],
      "lines": [
        {
          "sequence": 1,
          "speaker": "shop",
          "english": "Hi, how can I help you?",
          "tts_text": null,
          "learning_note": null,
          "translations": { "bn": "নমস্কার, আমি কীভাবে সাহায্য করতে পারি?" }
        },
        {
          "sequence": 2,
          "speaker": "cust",
          "english": "This headphone arrived damaged. Can I get a refund?",
          "tts_text": null,
          "learning_note": "\"Can I get\" is a common, polite way to ask for something at a counter.",
          "translations": { "bn": "এই হেডফোনটি ভাঙা অবস্থায় এসেছে। আমি কি টাকা ফেরত পেতে পারি?" }
        }
      ],
      "exercises": [],
      "vocabulary": [
        { "lemma": "refund", "pos": "noun", "lines": [2], "gloss": { "bn": "টাকা ফেরত" } }
      ],
      "grammar": []
    }
  ]
}
```

Rules:
- `schema_version` must match the importer version. Unknown fields are rejected, so typos are caught.
- `sequence` must be contiguous from 1 per version.
- `speaker` keys must exist in that version's `speakers`.
- Imported content is always `draft`. Publishing is a separate, reviewed step.
- Audio is not part of the import. It is generated later (Audio Guide §4).

## 8. Review Workflow

| Step | Owner | Output |
|---|---|---|
| 1. Draft English | Editor | English scenario and versions |
| 2. Level check | Editor + reviewer (random 20%) | Level confirmed |
| 3. Automatic checks | System | Pass or flagged list |
| 4. Translation draft | Translator | Bangla lines |
| 5. Translation review | Bangla reviewer | Approve or reject with reason |
| 6. Grammar and vocabulary review | Reviewer | Approve notes |
| 7. Audio review | Reviewer (listen) | Approve audio per accent |
| 8. Final publish check | Reviewer | Publish |

A scenario can be published with missing optional assets (translation for one language, grammar notes). Publish validation (DB §7) blocks only missing required fields and broken references.

## 9. Review Checklists

### 9.1 English dialogue

- [ ] Sounds like real speech for the stated style.
- [ ] Level matches the signals in §4.
- [ ] Each longer version adds depth (no padding).
- [ ] No stereotypes, no real names, no invented facts.
- [ ] Learning notes are short and specific.
- [ ] Numbers and times written in speakable form.

### 9.2 Bangla translation

- [ ] Meaning, tone, and politeness match.
- [ ] Pronoun and address follow §5.2.
- [ ] Glossary terms used consistently.
- [ ] Line count matches English.
- [ ] No machine artifacts.

### 9.3 Grammar and vocabulary

- [ ] Every note refers to the actual sentence.
- [ ] No field is shown that does not apply.
- [ ] Automatic checks passed or the issue is resolved.

### 9.4 Professional content (extra)

- [ ] A subject-matter reviewer has approved it.
- [ ] Includes a note: "This conversation teaches English. It is not professional advice."
- [ ] No specific legal, medical, or financial instruction stated as fact.

## 11. Quality Targets for Phase 1

- Every published scenario: reviewed English, reviewed Bangla, reviewed grammar notes for key lines.
- At least 80% of Short-version lines have a grammar or vocabulary note.
- No published line with a known error.
- Level re-check passed for 20% random sample.
- Owner reads 3 scenarios end-to-end as a learner before the release gate.
